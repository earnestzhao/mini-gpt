# 一个完整的 LLM 由哪些部分组成

准备好开始了吗？我们就先从一个完整 LLM 的基本结构和模块组成谈起。

## 与人对话

不妨先来想象一个场景。有一天，你在和一个朋友聊天。这个朋友性格非常好，对你的问题有问必答，从来不会厌烦，而且他博古通今，几乎什么话题都能讨论几句。

很平常地，你问了一个问题：有羽毛的动物是什么？

他想都没想，直接回答：有羽毛的动物是鸟。

这个过程发生得非常快速且自然，以至于你和朋友都没想过，这中间，你们经历了什么样的过程。

那就让我们来扒一扒这个过程吧。首先，你把话说出来了：有羽毛的动物是什么？

这位朋友如果想理解这个句子，通常需要先理解其中词语的含义，以及它们组合在一起所表达的意思。因此，他先要把这句话拆解成几个词语。

比如，他做了这样的拆分：“有”，“羽毛”，“的”，“动物”，“是”，“什么”，“？”。

在真实世界中，和朋友聊天，大概率不会拆解标点符号。但这个信息是客观存在的，比如他可以通过你的语调来判断这是一个问句，相当于也获取了“？”的信息。我们不用过多纠结这点。

第二步，他要明白这几个词指代的含义。如果他不懂每个词的意思，同样是无法回答问题的。

比如“羽毛”，他要知道这个词代表了现实世界中的什么东西。如果他的认知里，“羽毛”和“石头”是差不多的意思，他是无法给出正确答案的。

第三步，他要懂得，他将给你提供什么信息。你想要的问题答案，显然应该是一种动物或者一类动物的名称。

因此，他需要知道，你说出的这些词语，是想得到一种动物或者一类动物的名称。他会在“一种动物”或者“一类动物”这个相近的语义空间中，调动他的知识作出回答。

第四步，这个最终的回答“有羽毛的动物是鸟”会从他的嘴里说出来。

还有很重要的一个条件。如果他是刚出生的婴儿，他不会对你的问题作出有效回答。他可以有效回答你的问题，和他多年的成长、学习、阅历、和经验密切相关。

## 与 LLM 对话

仔细想一想，假如把这位博古通今、不厌其烦、有问必答的可靠朋友换成 LLM，又当如何？

尽管 LLM 的实际计算机制与人脑并不相同，但从信息处理的角度看，我们可以把这两个过程划分成几个相似的步骤。只是每一步不是使用人脑，而是用一系列功能模块来实现的。

第一步，把句子拆解成词语的功能，由 Tokenizer 模块实现。

第二步，明白这些词语指代的意思，由 Embedding 模块实现。

第三步，懂得将要提供何种信息，由 Transformer 模块实现。

第四步，给出最终回答，由 Generator 模块实现。

最后的重要条件，就是 LLM 有效回答问题的能力，由 Trainer 模块实现。

因此，我们可以把一个完整的 LLM 系统划分为五个主要功能模块：Tokenizer，Embedding，Transformer，Generator，Trainer。它们之间的数据流关系如下图所示：

```text
           +-------------+      +-------------+      +---------------+      +-------------+
Input ---> |  Tokenizer  | ---> |  Embedding  | ---> |  Transformer  | ---> |  Generator  | ---> Output
           +-------------+      +-------------+      +---------------+      +-------------+
                                       ^                 ^       |
                                       |                 |       |          +-------------+
                                       |                 |       +--------> |   Trainer   |
                                       |                 |                  +-------------+
                                       |                 |                         |
                                       +-----------------+-------------------------+
```

图中不难看出，Generator 和 Trainer 位于两条 pipeline 之上。训练与推理（文本生成）是两种不同的运行过程，但它们会共享 Embedding，Transformer 等模型组件。一个没有训练好的 LLM（刚出生的婴儿或成长中的少年），不能直接用来回答问题。只有训练好的 LLM（博古通今、不厌其烦、有问必答的可靠朋友）才可以。

相信上面的类比，不难理解。接下来，我们用更加技术的语言，简要解释一下每个模块的功能和实现思路。

### Tokenizer

Tokenizer 的核心功能是将连续的文本切分成模型可以处理的最小单元，就是我们常说的 Token，并将它们转换为数字 ID 的表示，就是我们常说的 Token ID。它是连接人类语言和机器世界的桥梁，决定了模型处理语言的最小粒度。不同的 token 划分方法决定了 LLM 以什么样的方式来处理人类语言。

上文所举例的问题，“有羽毛的动物是什么？”，我们通过 Tokenizer，可以得到一系列的 Token 和 Token ID。例如：

| Token ID | Token |
| -------- | ----- |
| 23 | 有 |
| 112 | 羽毛 |
| 553 | 的 |
| 1038 | 动物 |
| 2143 | 是 |
| 3270 | 什么 |
| 4313 | ？ |

### Embedding

通过 Tokenizer，我们已经得到了一系列的 Token 和 Token ID。然而，单纯的 Token 和单一数字表示的 ID 无法建立任何语义信息，也无法构建 ID 之间的语义联系。

回到刚才的例子，LLM 已经拿到了 23, 112, 553, 1038, 2143, 3270, 4313 这一系列的 Token ID，在 LLM 看来，这些 ID 都是一个数字，没有任何本质区别。假如“石头”的 Token ID 是 157，那么单纯凭这些 ID，LLM 确实不知道 “羽毛”(112) 和 “石头”(157) 有什么区别，当然也就无法回答这个问题。

这个时候，就该 Embedding 登场了。Embedding 可以理解为将 Token 映射到一个高维的语义表示空间。在这个空间中，每个 Token 都被映射为一个高维稠密向量。例如：

| Token ID | Token | Embedding |
| -------- | ----- | --------- |
| 23 | 有 | [0.0626304, 0.126459, -0.0582043, ...] |
| 112 | 羽毛 | [-0.173733, -0.100062, -0.0194214, ...] |
| 157 | 石头 | [0.173759, 0.00167136, 0.0729713, ...] |
| 553 | 的 | [0.0608181, 0.0613651, -0.0755621, ...] |
| 1038 | 动物 | [-0.174222, -0.124878, -0.056266, ...] |
| 2143 | 是 | [-0.0682421, -0.100038, -0.00864957, ...] |
| 3270 | 什么 | [0.172209, -0.0708882, -0.0773443, ...] |
| 5186 | 鸟 | [-0.206716, -0.145065, -0.015243, ...] |

经过训练，这些向量能够承载与 Token 相关的语义信息，也可能包含语法、词形等其他语言特征。

我们知道，一个高维向量相当于高维空间中的一个坐标。在这个高维语义空间中，语义相近的词会被放在彼此接近的坐标位置，让模型能够捕捉到词语之间的“亲疏远近”。经过适当训练，模型会学习到这些 Token 之间的某些语义关联。至于这些关联如何体现在向量中，以及如何衡量向量之间的相似性，我们将在后续文章中讨论。

我们通常无法直接解释向量中的每个分量（也可以叫做维度或坐标轴）究竟代表什么，但模型可以利用这些向量进行后续计算。

### Transformer

这是 LLM 最核心的部分了。如上文所述，Transformer 让 LLM 懂得将要提供何种信息。为了实现这个功能，需要用到一个非常重要的自注意力机制，英文叫做 Self-Attention。利用 Self-Attention 机制，Transformer 可以计算序列中不同 Token 之间的关联，并结合上下文处理这些信息。它不仅了解单个词的语义，还能结合上下文理解多义词在上下文中所表达的真正含义（比如“苹果”在当前上下文中到底指水果还是科技公司）。Transformer 就像一个超级加工厂，把碎片化的语义向量融会贯通，提取出上下文中的关键信息，以及这些信息最终关注的结果，为下一步的文本生成和模型训练提供特征支持。

在这个例子中，Transformer 可以通过 Self-Attention，将“羽毛”和“动物”等 Token 所表达的信息联系起来，结合上下文判断我们究竟在问什么，并为后续生成“鸟”这个答案提供依据。

### Generator

Generator 的职责是根据 Transformer 提取出的上下文特征信息，来预测下一个概率最高的 Token 是什么，或者以一定的概率规则生成下一个 Token。它采用自回归（Autoregressive）的方式，生成一个 Token，再把这个 Token 丢回输入端，继续按照相同的概率规则生成下一个 Token，直到吐出完整的答案。

本例当中，Generator 的大致工作模式如下：

| 当前输入 | 计算 | 概率最大的下一个 Token |
| ------- | ---- | ------------------- |
| Q: 有羽毛的动物是什么？ | Tokenizer, Embedding, Transformer | A: |
| Q: 有羽毛的动物是什么？ A: | Embedding, Transformer | 有 |
| Q: 有羽毛的动物是什么？ A: 有 | Embedding, Transformer | 羽毛 |
| Q: 有羽毛的动物是什么？ A: 有羽毛 | Embedding, Transformer | 的 |
| Q: 有羽毛的动物是什么？ A: 有羽毛的 | Embedding, Transformer | 动物 |
| Q: 有羽毛的动物是什么？ A: 有羽毛的动物 | Embedding, Transformer | 是 |
| Q: 有羽毛的动物是什么？ A: 有羽毛的动物是 | Embedding, Transformer | 鸟 |
| Q: 有羽毛的动物是什么？ A: 有羽毛的动物是鸟 | Embedding, Transformer | 。 |
| Q: 有羽毛的动物是什么？ A: 有羽毛的动物是鸟。 | Embedding, Transformer | `<EOS>` |

### Trainer

Trainer 负责在模型训练阶段，把海量的数据喂给模型，通过上面描述的计算过程（前向传播计算）得到误差 Loss，再通过反向传播（Backpropagation）计算梯度，进而调整模型参数，包括 Transformer 参数和 Embedding 分量值。有了 Trainer 的帮助，模型就可以顺利地从“随机乱猜”的小婴儿，成长为“博古通今”的可靠朋友，从而对我们提出的问题作出有效回答。

本例当中，模型没有训练好之前，可能给出的回答是“羽毛石头是动物”或者“今天天气真好”。随着训练进行，模型通常会逐渐学到数据中的规律，训练损失整体呈下降趋势。经过充分而有效的训练，模型就可以对许多问题给出合理有效的回答。

## 总结

相信你已经知晓一个完整的 LLM 由哪些部分组成了。本篇的重点就是 LLM 的组成模块 Tokenizer，Embedding，Transformer，Generator，Trainer 和它们的作用，以及上面的数据流关系图。关于每个部分的具体内容和实现，在后面的篇目中会详细说明。
